# 21-采用与验证计划 v1.0

> 定案时间：2026-10-12 · 来源：WorkBuddy 与项目总经理的**五轮问答**（由「我们一直在绕的深层问题」引出）。
> ★ 本文是「系统建成之后，如何走向正式投用」的**口径记录** —— 此前该话题从未被显式讨论，特此固化。

## 1. 职责边界（先划线）

| 域 | 内容 | 由谁管 |
|---|---|---|
| **系统域** | 数据正确性、权限、审计（谁改了什么）、追溯链 | 系统＋开发流程 |
| **制度域** | 用不用、怎么用、核对频次、奖惩、岗位职责 | **公司制度（管理层）** |

★ 例外说明：「人的行为」不进系统设计，但**人的行为的【痕迹】与【授权】必须系统管**（审计 / 权限）—— 此为两域的精确分界线。

## 2. 上线路径（四段式）

| 阶段 | 内容 | 通过条件 |
|---|---|---|
| ① **纸笔期（当前）** | 工厂试验阶段，纸质台账运行 | — |
| ② **功能实验** | 项目总经理本人使用系统 | 功能层面无阻塞问题 |
| ③ **双轨验证** | 各岗位「纸质＋系统」同步运行，**当日 24:00 前补录** | ★ **人工核对系统数据与纸质台账保持一致、数据不出错**（最核心判据） |
| ④ **正式投用** | 系统为准，纸质退为备份 | 双轨验证通过 |

## 3. 核心判据与口径

- ★ **最核心判据：人工核对系统数据与纸质台账保持一致，数据不出错。**
- ★ **人的行为（用不用、怎么用）由公司制度规范，不作系统判据**。
  ★ 但「补录率」是**核对得以开始的门槛**（无人补录 ⇒ 无数据可核 ⇒ 判据无法运行）——门槛不达标 ⇒ 延长双轨期 / 换录入方式 / 立制度。
- ★ **双轨期以纸质为事实来源**（真实工作流在纸上），系统为镜像与练手；**正式投用即反转**（系统为准，纸质退为备份）。
- ★★ **判据换轨**（投用后纸质退场，参照物改变）：

| 阶段 | 判据 | 依托模块 |
|---|---|---|
| 双轨期 | 系统 ＝ 纸质（**单据级**一致） | 录入链 |
| 投用后 | ① **内部链路自洽**（一袋成品可追到其检测结论与原料批次） | **追溯 M8** |
| | ② **外部抽查一致**（客户对账、供应商对单） | **报告分享 M9** |

## 4. 范围决策

- ★ **检测字段由后台定义、按客户不同**（`m_test_item` / `m_test_item_limit`）。纸质台账**结构**不作为对齐基准；**双轨核对的是「值」，不是「结构」**。
- ★ **检测数据导入（仪器软件导出 → 系统）不在一期**，一期手输；导入功能随设备接入另行立项。
- ★ **手持端（PDA 扫码、蓝牙标签打印）＝ 未来安卓 APP（另立项）**，不在网页端实现；一期网页端服务**质检岗（电脑）＋ 管理岗**。
- ★ 双轨期范围以**质检线先行**为推荐；生产/出货线是否纳入由用户决定（「再看」）。
- ★ 未分配角色的账号登录 ⇒ 提示「联系管理员」；**飞书组织同步**＝ 手动同步按钮 ＋ 后台事件回调（**入职建号 / 离职注销**）。
- ★ 登录提示文案：不写死联系人，就写「联系管理员」（公司内皆知）。
