## 1. 为什么这么分

1. **本机是工作机**（用户通过手机远程使用），不该被开发环境的进程、端口、依赖占用；
2. **测试服务器才是真环境**：MySQL 在那边、网络拓扑在那边、Caddy 在那边 —— 「本机能跑」不等于「部署起来能跑」；
3. **验收判据里有必须"真跑进程"的项**（如 `A4 会话跨重启仍有效`）—— **本机不跑服务就没法在本机验**，硬验只能变成推断。

## 4. 部署与运行（用脚本，不手敲）

```bash
# ① 准备本机（一次性）：把运行配置写到 .env.deploy（已被 .gitignore 覆盖）
cp .env.deploy.example .env.deploy   # 然后填 JX_DB_DSN 等

# ② 交叉编译 + 上传 + （可选）重启 + 健康检查
bash scripts/deploy-test-server.sh --restart --smoke
```

脚本做四件事：**交叉编译**（`GOOS=linux GOARCH=amd64`）→ **scp 二进制与配置** → **在服务器上起/重启服务**（`nohup` + PID 文件）→ **健康检查**。

★ MySQL 用的是**服务器上已有的容器** `jx-lab-trace-mysql`（绑 `192.168.10.50:3306`），**不要在本机起实例、不要建隧道**。
