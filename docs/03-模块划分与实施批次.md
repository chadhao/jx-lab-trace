# 模块划分与实施批次

> **定位**：把 `docs/01-设计定案.md` 的 38 张表 / 12 个页面模块，切成**可独立交办、可独立验收**的开发批次。
> **责任**：本文件归 **WorkBuddy**（产品设计域）；**实施批次的拆分与工作量评估归 mimo**（见 COLLAB.md §2），
> 即：本文给出**依赖顺序与验收判据**，mimo 若认为某批过大可以**回执建议再拆**。
> **建立日期**：2026-10-08

## 2. 实施批次（8 批）

| 批次 | 内容 | 依赖 | 验收要点（可判定） |
|---|---|---|---|
| **批 1** | **M0 地基** | — | ① `check_all.sh` 全绿可跑；② 迁移可重复执行（幂等）；③ 飞书免登 dev 模式可登入；④ **会话重启后仍有效**（本条必须实测：重启进程后原 cookie 仍可用）；⑤ 权限引擎：未授权一律拒绝（deny by default）；⑥ 权限点由代码注册、后台不可增删；⑦ 审计日志每笔写操作有记录 |
| **批 2** | **M1 主数据 + M2 权限配置页** | 批 1 | ① 8 类主数据增删改查可用；② **版本链**：改一次产生新版本、旧版本可查、`is_current` 唯一切换；③ ★ **判定限按「客户 × 物料」生效**（同检测项对 A 客户与 B 客户限值不同）；④ 权限矩阵页改一格 → 该账号行为立即变化；⑤ ★ **防锁死**：系统管理员的管理域权限置灰不可编辑；⑥ 权限变更写审计 |
| **批 3** | **M3 收货与打码** | 批 2 | ① ★ **码引擎**：`spec/code-rules.json` 的 **5 条示例向量全部通过**（生成 + 解析双向）；② 校验位错误码被**拒绝**且提示"请重扫"；③ 预报 → 到货确认 → 过磅 → 批量生成 N 个袋码全链可用；④ ★ **袋码在过磅确认后生成**（不在预报时预打）；⑤ 空号跳号不回收；⑥ 补打须填原因；⑦ 袋作废：**已取样/已投料的袋拒绝作废** |
| **批 4** | **M4 取样与留样** | 批 3 | ① 扫吨袋码生成份样 + 保留样；② 合并生成大样并把份样并入；③ **保留样与检测样各自独立跟踪**；④ 留样入库记位置与期限；⑤ 销毁须审批人 |
| **批 5** | **M5 检测** | 批 4 | ① 检测挂**大样**、不挂袋；② 结果三态（未测/已测/不适用）可录；③ ★ 有结果后**不能删项**、只能加项；④ 让步接收**四字段必填**（何时/告知谁/渠道 + 授权人）；⑤ 紧急放行**发起 ≠ 审批**（同一人不得兼任）；⑥ 复检不覆盖原结果 |
| **批 6** | **M6 生产与谱系** | 批 5 | ① ★★ **投料扫码写 `b_feed_record`**；② ★ 正向/反向谱系**数据可查**（一车 → 多批、多车 → 一批）；③ 作业段支持跨班组；④ 成品批 `code` 的序1 ＝ **来源生产批序**；⑤ 返工用新批号 + 关联原批 |
| **批 7** | **M7 出货 + M8 追溯** | 批 6 | ① 逐袋扫成品袋码归集成出货单；② ★ **同一成品袋不能被两个出货单归集**（唯一约束）；③ 出货撤销发起 ≠ 审批；④ ★★ **正向与反向追溯结果互为逆**（同一数据，两个方向必须一致） |
| **批 8** | **M9 报告分享 + M10 报表** | 批 7 | ① 生成报告 = 快照，**刷新 = 新 token 新链接**；② 链接过期/撤销后不可访问；③ 访问留日志；④ ★ **公网侧只有静态文件、不连内网库**；⑤ M10 **不写任何业务表**（可机检） |

## 3. 批次的推进规则

1. ★ **一批一验收**：批次未通过验收**不放行下一批**（防「后面盖在错的基础上」）。
2. ★ **每批交办前先跑门禁**：门禁不绿不交办（拿一个红的基线去交办，等于让 mimo 在错误前提上开工）。
3. ★ **每批交办前必须备齐该模块的用例与测试用例**（`docs/04-模块设计与用例.md`）——「对方拿到这段说明，能不问就做对吗？」不能 ⇒ 先补规格。
4. ★ **验收一律不采信自报**：复跑门禁 + 读实现 + 单点变异 + 还原核对。
5. ★ **mimo 有权回执建议再拆批**（见 COLLAB.md §2 责任域）：若某批实际过大，mimo 应**回执说明并拆分**，而不是硬做完或做一半。
