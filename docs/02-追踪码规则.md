# 追踪码规则 · 详细说明（v1）

> **状态**：★ **v1 已冻结**（2026-10-08 用户确认「编码暂时这样没问题」）—— 作为 mimo 实现依据；后续变更须走 §10 的版本位流程。
> **上游**：`docs/01-设计定案.md` §4
> **本文目的**：把「码怎么拼、谁生成、怎么解、出错怎么办」写到 **mimo 不需要再问人** 的程度。

---

## 0. 一句话

**一条链（原料链或成品链）内，所有对象共用同一个前缀；越往下走，序段展开得越深。**

```
原料链：  车次 ──→ 吨袋                    （2 层）
成品链：  生产批 ──→ 成品批 ──→ 成品袋    （3 层）
```

**跨链关系（原料 → 成品）不编码**，由投料记录（`b_feed_record`）承载 —— 见 §11。

---

## 1. 码结构总览

**全码 = 定长 27 位**：`裸串 26 位 + 校验位 1 位`

```
位序   1   2    3-4     5-8      9-12     13-18     19-20   21-23   24-26   27
段     V   T    BT      客户      物料      日期      序1     序2     序3     C
宽度   1   1     2        4         4         6        2       3       3      1
示例   1   A    CG      0001      0002     261007     03     000     000     L
```

| 段 | 名称 | 宽 | 取值 | 谁生成 | 说明 |
|---|---|---|---|---|---|
| **V** | 编码版本 | 1 | `1`–`9` | 常量 | 规则版本。结构变更时 **+1**，老码按老版本继续解析 |
| **T** | 对象类型 | 1 | `A`/`B`/`C`/`D`/`E` | 系统 | 决定序段的解释方式 |
| **BT** | 业务类型 | 2 | `CG`/`ZG` | 收货员选 | `CG` 客供（受托加工）· `ZG` 自购 |
| 客户 | 客户编号 | 4 | 数字，`0000` 保留 | 主数据 | 自购料（`ZG`）填 `0000` |
| 物料 | 物料编号 | 4 | 数字 | 主数据 | **原料对象填原料物料；成品对象填成品物料** |
| 日期 | 链根日期 | 6 | `YYMMDD` | 系统 | 原料链＝到货日；成品链＝生产批创建日 |
| **序1** | 第 1 层序号 | 2 | `01`–`99` | 系统 | 车序 / 生产批序 |
| **序2** | 第 2 层序号 | 3 | `001`–`999` | 系统 | 袋序 / 成品批序 |
| **序3** | 第 3 层序号 | 3 | `001`–`999` | 系统 | 仅成品袋用（袋序） |
| **C** | 校验位 | 1 | `0-9A-Z` | 系统算 | 见 §7 |

**字符集**：`0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZ`（36 个，值 0–35）。

## 2. 对象类型与「三层序」的对应

★ **关键规则：序段表达的是「从链根到本对象」的完整路径，不是本对象自己的流水。**

| T | 对象 | 序1 | 序2 | 序3 | 层级深度 |
|---|---|---|---|---|---|
| `A` | 车次 | 车序 | `000` | `000` | 1 |
| `B` | 原料吨袋 | 车序 | 袋序 | `000` | 2 |
| `C` | 生产批 | 批序 | `000` | `000` | 1 |
| `D` | 成品批 | **来源生产批的批序** | 成品批序（该生产批内第几个） | `000` | 2 |
| `E` | 成品吨袋 | **来源生产批的批序** | 成品批序 | 袋序（该成品批内第几袋） | 3 |

★ **原料链只有 2 层，所以原料链上「序3」恒为 `000`。**
这不是「没用的死位」，而是「**原料链的层级深度只有 2**」的正常表达 —— **该段有明确定义（恒 `000`）**，与「未定义、可被随便填」是两回事。

★ **为什么 `D`/`E` 的序1 必须是「来源生产批序」而不是自己的流水？**
因为只有这样，**成品袋码才自带完整祖先链**：工人扫一袋成品，从码上就能读出它属于哪个生产批、哪个成品批 —— 不用查库。这是「码携带身份」的价值所在（原则 P2）。

## 3. 完整示例（已用脚本核算过校验位）

统一设定：客户 `0001`（客供）· 原料物料 `0002` · 成品物料 `0003` · 日期 `2026-10-07`

| T | 对象 | 裸串（26 位） | +校验 | 人读行 |
|---|---|---|---|---|
| `A` | 车次（当日第 3 车） | `1ACG0001000226100703000000` | **`L`** | `1A-CG-0001-0002-261007-03-000-000-L` |
| `B` | 该车第 7 袋 | `1BCG0001000226100703007000` | **`7`** | `1B-CG-0001-0002-261007-03-007-000-7` |
| `C` | 生产批（当日第 3 批） | `1CCG0001000326100703000000` | **`O`** | `1C-CG-0001-0003-261007-03-000-000-O` |
| `D` | 生产批 03 的第 2 个成品批 | `1DCG0001000326100703002000` | **`V`** | `1D-CG-0001-0003-261007-03-002-000-V` |
| `E` | 上述成品批的第 15 袋 | `1ECG0001000326100703002015` | **`4`** | `1E-CG-0001-0003-261007-03-002-015-4` |

**读法演示**（成品袋 `1E-…`）：
```
1   E      CG    0001     0003      261007    03    002     015    4
↑   ↑       ↑     ↑        ↑          ↑       ↑      ↑       ↑     ↑
v1  成品吨袋 客供  客户0001  成品物料0003 2026-10-07 生产批03 第2个成品批 第15袋 校验
```

★ **注意 `C`（生产批）的物料段填的是「产出成品物料 `0003`」，不是投入原料物料。**
理由：生产批按**将要产出的成品**排产编号；这样 `C`/`D`/`E` 三者在同一条链上**物料段一致**，序段才能层层引用。
**投入了什么料，查投料记录**（`b_feed_record`）。

## 4. 序号空间与分配规则

| 序段 | 序号空间 | 上限 | 备注 |
|---|---|---|---|
| 车序 | `客户 + 原料物料 + 到货日` | 99 车/日 | |
| 袋序 | 车内 | 999 袋 | |
| 批序 | `客户 + 成品物料 + 生产批创建日` | 99 批/日 | |
| 成品批序 | 生产批内 | 999 个 | |
| 成品袋序 | 成品批内 | 999 袋 | |

**规则：**

1. ★ **空号跳号不回收**。预报已分配车序但车未到（或预报取消）⇒ 该序号作废，**不重新分配**。
   > 回收会让「同一车序在不同时间指向两辆车」，历史记录出现歧义。**空号不可怕，歧义很可怕。**
2. ★ **并发取号必须串行化**。两个收货员同时给同一「客户 + 物料 + 日期」录预报时，取号必须在**同一事务**内完成（`SELECT ... FOR UPDATE` 或数据库序列），**禁止"先查最大值再 +1"**。
   唯一性最终由 **数据库 UNIQUE 索引**兜住 —— 冲突时报错重取，**不靠人眼**。
3. ★ **超限不自动进位**。序号超上限（如当日第 100 车）时**明确报错、由人决策**，绝不自动加宽段位 —— 加宽会破坏定长，整套解析规则失效。
4. **日期段取「链根日期」**，跨零点不重编：原料链＝到货日，成品链＝生产批创建日。
   对象的**实际发生时间**（卸货时间、产出时间）**编码里不体现**，存库（`arrive_at` / `produced_at`）。
5. **改预报不改车序**：预报录错（车牌/物料错）时，**车序保持不动**，只改其他字段 —— 否则会与已打印的标签对不上。

## 5. 三种"码面"

| 码面 | 内容 | 用途 |
|---|---|---|
| **二维码内容** | **裸串 27 位**（无分隔符），如 `1ECG00010003261007030020154` | 机器扫读 |
| **人读行** | 带分隔符的全码，如 `1E-CG-0001-0003-261007-03-002-015-4` | 人眼核对；与裸串**严格同构**，可双向转换 |
| **手输通道** | ★ **不设独立短码** —— 手输走「**先选父对象，再输本层序号**」 | 扫码设备全不可用时 |

★ **人读行的分组宽度**：`[2, 2, 4, 4, 6, 2, 3, 3, 1]` —— ★ **与段定义的分组「不同」**：人读行把「**版本 + 对象类型**」合并成 2 位的「**对象头**」（读作 `1A` / `1E` 比 `1-A` / `1-E` 更自然）。
⇒ 这个分组是**显示格式的一部分，必须显式声明**，否则人读行与裸串**无法严格互转**（★ 这一条是机读规格自校验脚本发现的，见 §13）。

★ **为什么不设短副码**：短码会引入"第二套编号"，需要单独维护唯一性、还要防止与主码混淆。而**扫码设备全不可用的场景，现场几乎总有一部手机可以扫**（系统是 Web H5，手机浏览器可直接调摄像头）。真到了只能手输的地步，「选父 + 输 3 位袋序」比输任何短码都更少出错。

**印刷建议**：人读行中**全零段（`000`）用更浅的字色、更小的字号** —— 降低噪音，但**仍然印出来**，保证人读行可被机器重新解析。

## 6. 标签规范

| 项 | 规定 |
|---|---|
| 材质 | **热转印 / 热敏不干胶**（车间有粉尘油污，普通纸撑不住） |
| 内容 | 二维码（≥ 20×20 mm）＋ 人读行 ＋ 可选：「客户简称 / 物料名 / 序号」大字 |
| 二维码容错等级 | **M 级**（约 15% 破损可读）；标签易磨损，不建议 L 级 |
| 打印路径 | **服务端生成标签版式页 → 浏览器打印到标签机**（一期**不写打印驱动**） |
| 补打 | ★ **必须填原因并留痕**（`b_label_print.is_reprint`），否则会出现"一物两码" |
| 批量打印 | 收货按实际袋数**批量生成 + 批量打印**（30 袋逐张单打会拖垮收货窗口） |

## 7. 校验位算法（可直接实现）

**字符值**：`0-9` → 0–9；`A-Z` → 10–35。

**步骤**：

1. 取裸串**前 26 位**（不含校验位）；
2. **从右向左**遍历，第 1 位（最右）权 **1**、第 2 位权 **3**、第 3 位权 1 …… **1/3 交替**；
3. `S = Σ 值(cᵢ) × 权ᵢ`；
4. `校验值 = S mod 36`，映射回字符集（`0-9A-Z`）。

**示例核算**（车次 `1ACG0001000226100703000000`）：

```
加权和 S = 93   →   93 mod 36 = 21   →   字符集第 21 位 = 'L'
```

**强度说明（诚实交底）**：

- **单字符替换漏检率 ≈ 1/36 ≈ 2.86%**（实测 20000 次随机单字符改动：572 次漏检）。**即能挡住约 97% 的手输错字**。
- ★ **相邻字符换位 100% 可检出**：交换两位会使加权和变化 `±2×(v₁−v₂)`，只有两字符**完全相同**时才为 0 —— 而相同字符互换本就看不出来。
- ★ **1 位校验位不防伪造**。防伪造靠**权限 + 审计**（原则 P3），不靠码。

## 8. 生成时机

| 码 | 触发动作 | 说明 |
|---|---|---|
| **车次码 `A`** | 「到货确认」时 | 预报阶段已分配车序，**到货确认才生成完整码** |
| **袋码 `B`** | **过磅确认后**按实际袋数批量生成 | ★ **不按预报袋数预打** —— 预报与实际不符会作废一堆标签 |
| **生产批码 `C`** | 建生产批时 | |
| **成品批码 `D`** | 生成成品批时 | |
| **成品袋码 `E`** | 成品袋生成时 | |

**流程串起来：**

```
客户告知车辆信息 → 录【预报单】→ 系统分配车序（暂不生成完整码）
  → 车到场点「到货确认」→ 生成车次码 A
  → 地磅过磅 → 录毛重/皮重 → 算净重 → 录实际袋数 N
  → 批量生成 N 个袋码 B → 批量打印 → 逐袋贴标
  → 车/袋进入「待检」
```

## 9. 解析规则（扫码之后怎么走）

```
扫码得到裸串 s（27 位）
  ├─ 长度 != 27        → 拒绝：「不是本系统的码」
  ├─ s[0] not in 1..9  → 拒绝
  ├─ s[1] not in ABCDE → 拒绝（对象类型未知）
  ├─ 校验位不匹配       → 拒绝：「码可能被读错，请重扫」（★ 关键的一步）
  └─ 通过 → 按 V 取版本、按 T 取布局 → 切分各段
       → 用「客户 + 物料 + 日期 + 序段」定位对象（唯一索引）
       → 命中 → 打开该对象页面
       → 未命中 → ★ 明确提示「码格式正确但系统内不存在」（可能：码印错 / 数据未同步）
```

★ **校验位在解析链的第一步就挡住了"读错码"**，避免把 A 袋的结果挂到 B 袋上 —— **这正是校验位存在的全部意义**。

## 10. 版本演进（V 位怎么用）

| 变更类型 | 处理方式 |
|---|---|
| 改**字段宽度**、**增删段**、**改段含义** | **V + 1**，新码用新版本；**老码按老版本照常解析** |
| 改**序号空间**（如车序改成全局流水） | V + 1 |
| 改**校验算法** | V + 1 |
| 只改**主数据取值**（客户改名、物料重编号） | ★ **不升版本** —— 码里存的是编号，编号不变则码不变 |

★ **版本位存在的唯一理由**：吨袋标签贴在实物上、留样要存很久；没有版本位，**任何一次编码体系调整都会让存量标签变成废纸**。1 位成本换这个，值。

## 11. 码与库表的分工（★ 最容易搞错的地方）

| 信息 | 在码里？ | 在哪 |
|---|---|---|
| 客户 / 物料 / 链根日期 / 逐层序号 | ✅ | 码段 |
| 业务类型（客供/自购） | ✅ | 码段 |
| **车次 → 吨袋** 归属 | ✅（袋码含车序） | 码段 |
| **生产批 → 成品批 → 成品袋** 归属 | ✅（序段层层展开） | 码段 |
| ★ **原料车次 → 生产批**（投料谱系） | ❌ **多对多，编不进定长码** | `b_feed_record` |
| ★ **生产批 ↔ 成品批**（若成品的物料段与生产批不同的场景） | ❌ | `b_fg_lot.batch_id` |
| 毛重 / 皮重 / 净重 | ❌ | `b_truck_lot` |
| 检测结果 / 判定 / 附件 | ❌ | `b_inspection*` |
| 实际发生时间 / 操作人 | ❌ | 各表字段 |

★ **判据（原则 P2）**：**码只表达「这是谁」和「它在自己链上的位置」；一切多对多关系与业务数据一律存库。**任何试图把谱系编进定长码的设计都会失效。

## 12. 边界与异常

| 场景 | 处理 |
|---|---|
| 一车只装一种物料？ | ★ **是业务前提** —— 码里车次只有一个物料段。混装车**按拆单处理**（一车录两条车次） |
| 自购料（`ZG`）没有客户 | 客户段填保留值 **`0000`** |
| 袋数录错（30 录成 28） | ★ **不改正、不删行**（原则 P1）：多余袋走「**作废**」动作（填原因 + 留痕），**作废码永久不重用**；`bag_count` 按**有效袋数**计 |
| 作废的袋已取样/已投料 | ★ **不允许作废** —— 说明现场已经用过它 |
| 跨零点卸货 | 日期段仍取**到货日**（车次码在到货确认时生成） |
| 客户临时派车、无预报 | 允许「**直接到货**」：现场补录预报并立即确认，车序照常分配 |
| 序号超上限 | **明确报错，人决策**（见 §4.3） |
| 标签破损看不清 | 走**补打**（留痕）；或用手输通道（选父 + 输序号） |
| 扫码扫到别的系统的码 | 解析第一步即拒绝，提示"不是本系统的码" |

## 13. 机读规格与自校验（★ 已完成）

本规则已抽成机读规格，供代码与门禁消费：

| 文件 | 作用 |
|---|---|
| `spec/code-rules.json` | 段定义 · 对象类型与层级 · 序号空间 · 校验算法参数 · 生成时机 · 解析步骤 · **5 条示例向量（含核算过的校验位）** · 人读行分组宽度 |
| `spec/verify_code_rules.py` | **规格自校验**：段宽之和 · 校验位复算 · 人读行同构 · **「三段序 = 三层嵌套」不变量** · 相邻换位可检出性 |

★ **为什么要自校验**：**校验位算错属于「看起来对、用起来才发现」的那类缺陷**。示例向量一旦进规格，就成为实现方的固定回归用例 —— **它自己必须是对的**。

★★ **这个脚本在第一次运行时真的抓到了一处不一致**：我声明的人读行把「版本 + 对象类型」合并成 2 位对象头（`1A-…`），而按段定义逐段拼会得到 `1-A-…`。
⇒ ★ **判据：凡是"声明了一套格式、又提供了生成算法"的地方，必须让它自己复算一遍** —— 否则这种"两边都合理、就是不一致"的问题会一路带到实现里。
